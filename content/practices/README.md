# practices/ — 创造者实践经验笔记（共创通道）

这里是**内容与代码分离**的核心通道：把实践经验写成文件放进这个目录，
即进入产品的上下文组装管线，随下一次对话生效。**中文为单一事实源**——
只用中文书写，AI 会用用户的界面语言转述「创造者的经验」，不需要你翻译。

## 写作约定

一个文件一段经历/一个主题，文件名用日期+主题（如 `2026-09-08-允许清单第一周.md`）。

frontmatter 必填字段：

```yaml
---
date: 2026-09-08          # 笔记日期
type: fact                # fact=我做了什么、发生了什么 / opinion=我认为、我倾向
stage: 2                  # 主要相关阶段 1-4（看见/松动/练习/活法）
tags: [允许清单, 实验]     # 可选，便于将来检索
---
```

正文自由书写，建议长度 200-800 字。写完提交进 git 即生效（构建产物
`src/generated/content.json` 由 `pnpm build-content` 重新生成）。

### 事实与观点的区别（重要）

注入 AI 上下文时会按 type 决定措辞：

- **fact**：客观发生的事。AI 会如实转述「创造者做过 X，结果是 Y」。
  例：「我用允许清单试了两周，第一次给自己点了 40 块的外卖，没有负罪感。」
- **opinion**：你的判断和倾向。AI 会标注为「创造者的经验/观点」转述，
  不当作事实陈述。例：「我觉得愧疚感消退发生在第三天，而不是第一天。」

拿不准就写 opinion——宁可被当观点，不可让推测被当事实。

### 注入规则（系统保证，不用你操心）

- 只注入与用户当前阶段（stage 匹配）相关的笔记，不是全量裸注入
- 与阶段引导语冲突时，阶段文件的 `ai_stance` 优先，笔记是补充视角
- 安全规则永远优先于笔记内容
- 写入权限仅创造者/管理员（git 仓库权限控制），用户不可写
