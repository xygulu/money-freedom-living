# 10 · P0 开跑前置设计（认知层闭环 / 6 节点 / 首启重排 / 邮件真跑通）

> **性质**：**设计稿**，可直接作为编码依据。来源：`docs/08-待修清单.md` P0 四条 ＋ `docs/07 附C 优化建议`。
> **为什么这四条是"开跑前置"**：`20-1` 判定表要求**行为层与认知层成对**才能判机制成不成立，并明写"行为层达标但认知层不达标＝机制在空转"。**只采行为层，跑完也得不出结论** —— 所以不补就跑，验证结果作废。
> **一条贯穿的约束**：**不能为了采集给用户加第三个日常任务。** 采集必须挂在用户本来就要做的事上（今天的动作、今天的一句话、那一封信）。

## 0. 一句话总纲

> **一天只有一件事要做**：做完那件事，回来交**一格**（三行，都可跳过）。
> 这一格同时喂四个东西：**即时见证**（用户体验）、**每日两问**（认知层）、**L4/L5/M**（三个指标）、**节点判断的原料**（`node_verdict`）。

## P0-1 · 认知层闭环：一格里同时采完 L4 / L5 / M

### 1.1 界面：「合」压成一屏三行（**一格提交**）

用户做完今天那件事，进来看到（不再跳 `/chat`）：

```
今天到这里                           ← 标题就一句，不要"提交""完成"这类词

① 我做了吗？      [ 做了 ] [ 没做完 ] [ 今天没顾上 ]      ← 单选，必须有一个
② 我想到什么？    [__________________________]           ← 一行，可留空
③ 脑子里第一句话  [__________________________]           ← 一行，可留空，可点"想不起来"
                  [ 今天到这里 ]                          ← 一个按钮收尾
```

- **三行都可跳过**（①②③ 任意留空仍可提交）—— **可跳过是硬要求**，否则第③问会变成负担，反而压垮自发继续率。
- 提交后**立刻**给一句回应（用 ②③ 里的原话回，不评价、不给结论），再出现「今天到这里」。**回应必须是"我听见了"，不是"你做得对"。**
- **不出现**：进度条、连续天数、红色提醒、未读点。

### 1.2 采集落点（**零新表**）

| 指标 | 定义 | 从哪来 | 落库位置 |
|---|---|---|---|
| **L5 停顿** | 用户第一次**主动停下来**看自己（不是被问） | 第③问**填了内容**（非空、非"想不起来"） | `threads[].evidence` 新增一条 `kind:'pause'`，`quote`＝用户原话 |
| **L4 迁移** | 用户**自己说出**一个新做法/新解释 | AI 识别到「和之前不一样的说法」，**给一个**一键记的按钮：`这是新的，记下来` ＋ `不对，撤销` | 点了「记下来」→ `kind:'migrate'`；点「撤销」→ **删除该条**（真的删，不留痕） |
| **M 恢复时间** | **掉回旧模式**到**回到新说法**之间的天数 | 第③问的文本**回到旧句式**（与历史 `pause`/`migrate` 的原话同族）→ 记 `kind:'regress'`，`at`＝当天；下次出现新说法时算差 | 同一 `threads[].evidence`，`kind:'regress'`；**天数由读取端算，不落库** |

> **为什么 L4 必须"AI 识别 + 一键记 + 可撤销"**：让用户自己判断"这算不算迁移"＝把测量负担推给用户，且不可靠。**AI 提议、用户确认**是唯一既准又不加负担的做法。
> **为什么 M 不用新交互**：它只是"第③问的文本与历史比"，**纯读取端计算**，用户无感。
> **⚠️ L4 的撤销必须是真删**：这是"不诊断、不贴标签"红线的技术实现 —— 用户说不对，那就当没发生过。

### 1.3 每日两问协议（写进 `prompt.ts` 的**硬约束**）

现状：`prompt.ts` 只有开场一句"最多一个轻轻的问题"。**要补的是协议，不是话术**：

1. **一天最多两个问题**，且**不同时出现**（第一个回答完，才可能出第二个；答不出就不出）。
2. **两问的顺序固定**：
   - 第一问**问行为**：指向"今天这一小步"（例：「那一句，你写了吗？」）
   - 第二问**问认知**：指向"你脑子里冒出来的那句话"（例：「写的时候，脑子里先冒出的是哪一句？」）
3. **五类失败接法**（这一类必须逐条实现，否则陪伴会变成审讯）：

| 用户的反应 | 接法（**禁止**追问、禁止复述问题、禁止"为什么"） |
|---|---|
| 说"没做" | 接住，不评价；**给一个更小的一步**（"那把它拆到一句话就够了"） |
| 说"不知道 / 想不起来" | **放行**："那就先放着" → 结束当天 |
| 只回一个字（"嗯""好"） | **不追问**，回应一句然后收尾 |
| 反问回来（"你说呢"） | 把问题**还给他**，不代替他回答 |
| 情绪为负（烦 / 累 / 不想谈） | **停**：不给动作、不给建议；只接住情绪，然后「今天到这里」 |

4. **任何时候用户说"别说这个了"** → 立即停止该话题，**当天不再问**。
5. **两问之外**不许夹带第三个问题（包括"要不要试试…"）。

> **验收方式**：造 6 个会话（每类失败各一），逐个核对 **AI 的下一句** —— 是否符合上表。**这在 `vitest` 里做不了**，必须走 `scripts/` 下的真模型冒烟脚本。

## P0-2 · 6 节点闭环：邮件带回一个问题 → 一格 → 三态判断

### 2.1 六个节点各问什么（**每个节点回答不同的问题，且是决策点**）

| 节点 | 问的问题 | 判什么 |
|---|---|---|
| **D7** | 动起来没？ | 有没有真的开始 |
| **D14** | **机制成不成立** ← **主判断点** | 行为层 × 认知层成对看 |
| **D21** | 没人催，还在做吗？ | **能不能断奶**（是否依赖推送） |
| **D30** | 认知有稳定方向了吗？ | 说法是否收敛 |
| **D66** | 行为自动化了吗？ | 有没有变成习惯（**唯一有科学依据的节点**，Lally 中位 66 天） |
| **D90** | 成了吗？愿意继续吗？ | 值不值得续 |

### 2.2 机制：邮件 → 回程 → 一格 → 落库 → 三态

```
节点日 → 邮件带那一个问题（复用 src/lib/touch.ts）
       → 邮件里的链接带 ?from=touch&node=D7
       → 回程页面 = 「一格提交」（同一个组件，不另做页面）
       → 提交后写 events(name='node_verdict', ...)
       → 三态判断 → 结论 / 提前收官
```

**`events.node_verdict` 建议字段**（走既有 `events` 表，**零 DDL**）：
`name='node_verdict'`，`meta` 内：`node`（D7/14/21/30/66/90）、`verdict`（`yes`/`no`/`pending`）、`behavior_ok`、`cognition_ok`、`basis`（依据的用户原话）、`source`（`touch`/`app`）。

- **三态**：`✅成立` / `❌不成立` → **提前收官**；`⏳待续` → 进下一阶段。
- **收敛速度**：另记"第几天 / 第几版开始达标"（这是成功信号，不是附加项）。
- **提前收官必须写明"这次验证没回答什么"**（例：D14 收 → 没答"断奶""自动化"）。

### 2.3 边界（防止把验证跑成 KPI）

- **D66 / D90 只做个案**，不做定量 —— 样本衰减，硬做定量是自欺（`20-1` 已定）。
- 节点**不是"必须跑完 6 个"**：每个节点都可能是终点。
- **验证收官 ≠ 产品停**。

## P0-3 · 首启重排：3 分钟内被说中，问卷拆进对话

**现状**（线上实测）：一屏 6 题（含 2 道开放题），**答完才能继续** → "第 2 分钟被说中"**不可达**。

**目标**：**首屏不出现问卷**；先给一件小事 → **在对话里**拿到"被说中"那一句。

顺序改为：

1. **首屏**：一句欢迎 + **直接开始一段对话**（不问任何题）
2. **对话里**逐步拿到必要信息（每次一句，能跳过）
3. **"我听到的是…"**（已有，`M11-C`）必须在**前 3 分钟内**出现，且用**对话里用户自己说过的词**
4. **问卷/体检**（原 6 题）**挪到"被说中"之后**，且**拆成多段**，不一次给 6 题
5. **同意**（`ConsentKind='sensitive'|'touch'`）仍在"被说中"之后 —— 现有实现是对的，**别动这个顺序**

**验收**：真浏览器走一遍，**JS 读 DOM 文本**测时；`events.first_echo_shown` 里 `seconds < 180` 才算过（现有埋点已有 `seconds` 字段）。

## P0-4 · 邮件真跑通（**以真实到达为准，不接受"代码已实现"**）

现状：通道已通、样信寄过，但库内 `emailOptIn=true` = **0/155**、`sentNodes` 非空 = **0**、`consent_records.kind='touch'` = **0 条**。

1. **opt-in 必须进游客/首启路径** —— 现在 `{user && <TouchOptIn/>}`，**游客永远进不了触达**（这也是 P1-6 的同一根因）。
2. **真发一封给真人收件箱** → **确认到达** → 文案不落垃圾箱。
3. **退订可用**：GET 送确认页（零副作用）、POST 才真退（已实现，需真跑一次）。
4. **归因跑通**：`?from=touch&node=D7` → 记 `touch_return`。
5. **上线前**：`_dmarc.miller.ink` TXT ＋ **换自有发信域名**（现借 `miller.ink`）＋ SPF/DKIM 齐。

> **验收标准（照 `docs/08 附D`）**：**真实邮箱收件箱为证 + 退订链接可用**。**不接受"代码已实现"、不接受"样信寄过"。**
