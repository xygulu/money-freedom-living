## 4. 产品优化建议

> 排序原则：**先让"验证"这件事成立，再让产品更好用**。

### 优化 1 · 把「合」做成节点采集器（**一箭四雕**，最高优先）

现在「合」＝跳去 `/chat`，是个**导航**，不是**采集点**。改成**一格提交**：

```
① 我做了     [✓ 就是这个] [换一个] [今天跳过]     ← 一次点击即确认
② 我想到     [ 一句话 / 语音 ]                    ← 「证」
③ 脑子里第一句话 [ 一句话，可跳过 ]                ← 「叙」＝认知层唯一入口
        [ 交给他 ] → 即时见证回应 +「今天到这里」
```

**这一个改动同时解决四件事：**
1. **P0-1** 每日两问有了确定性落点（不依赖 AI 主动问到 —— AI 问不到就漏采）
2. **P0-3** 第③问有了界面
3. **P0-2** L5 停顿的采集入口（第③问）
4. **P1-5/12** 邮件唤回的人回来有**明确的一件事可做**，且**可归因**

**硬规矩不变**：②③ 可跳过；③ **跳过不惩罚、不暗示"建议填写"**（它是照见工具，不是作业）。

### 优化 2 · 认知层三个指标全部"零成本化"

| 指标 | 采法 | 用户成本 |
|---|---|---|
| **L5 停顿** | 「合」的第③问（每天出现，可跳过） | 1 句话 |
| **L4 迁移** | AI 在对话里识别到"意外用上了新说法" → 给一个**一次性按钮**"记下来"（**必须可撤销**） | 1 次点击 |
| **M 恢复时间** | **不新增交互**：定义"掉回旧模式"＝第③问的答案回到旧的自动化句式（AI 判定 + 用户可撤销），记进 `threads[].evidence` 加 `kind:'regress'`，**零新表** | **0** |

**原则**：**不能为了采集而给用户加第三个日常任务。**
**反指标一起记**：形式化打卡率 + 敷衍率（门槛数字**无依据**，标注"第一轮跑完修正"）。

### 优化 3 · 6 节点闭环：邮件 + 一格提交

每个节点＝**一封带问题的信** → 用户回来答一格 → 结论落 `events.node_verdict`（`{node, verdict: 成立|不成立|待续, metric, value}`）→ 三态判断 → 决定是否提前收官。

> 邮件不是"催他回来"，是**那个节点的采集载体**：信里只说那个节点要回答的那一件事 + 他自己的原话。
> 这样 `20-1` 的"**提前出结论**"才有机器；否则 90 天只是一个期限，不是一个能出结论的过程。

### 优化 4 · 「悬着的东西」清单（**召回引擎的产品内一半**）

邮件是**外部**一半；产品内还缺一半。把用户**自己的未完成**做成可见清单：

- 开放中的 `concerns`、写了半句的信、上次说到一半的事
- **可见、可点开、不可清零**（不清零 ＝ 不制造欠账）
- 放在 `/road`（"还没走到的地方"旁边）或首页「路」的留白处

> 对标《纪念碑谷》：**远处那座看得见、今天走不到的塔**。

### 优化 5 · 首页「路」的"你上次留在这里"

`docs/06 §2.2` 画了"昨日回响"（引用他昨天留的一句话，**没有就留白、不占位**）。**需确认是否已实现**；这是**最便宜的"被记住"体感** —— 比任何一份报告都有效。

### 优化 6 · 触达的"信"再往前一步

- **D66 / D90 的信附"带走的物件"**：《我脑子里的那几句话》的中间版（他自己的原话拼的，**不给结论**）
- 引用他写过的**信**，并说"它还在"—— 信是产品原生形态，这句话最像人话

### 优化 7 · 多书：区域需要"不同的世界"

现在 `/road` 有跨书站点，但第二本书进来时用户要感觉到**"地图变大了"**而不是"又多了一门课"。
→ 每个区域给**独立的意象 / 色调**（对标《纪念碑谷》每章不同的世界）。这条是接第二本书时才需要，但**内容层要提前留字段**。
