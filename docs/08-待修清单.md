## 附D · 怎么验（每类问题的可验收标准）

| 类别 | 验收方式 |
|---|---|
| 认知层三指标 | 真走一遍首启 → 日频 →「合」第③问，**在库里查到对应字段**（`threads[].evidence.kind='regress'` 等） |
| 6 节点 | 造一个 D7 用户（或改 `created_at`）→ 触发节点 → **库里出现 `events(name='node_verdict')`** |
| **外部通道（邮件/通知）** | **以真实到达为准**：真邮箱收件箱为证 + 退订链接可用。**不接受"代码已实现"** |
| 界面 / 文案类 | **JS 读真实 DOM 的 `innerText`**，不看截图（长截图会产出布局假象） |
| 数据 / 结构类 | 只读查库（`information_schema` + 实读行）；文档改动以 `docs/03 §11` 有条目为据 |
| 任何"缺失"结论 | 必须同时给出**三证**：`grep` 结果 + 库内/事件表查询 + 界面实读；缺一就降级为"待验"，不写成待修 |

## 附C · 优化建议（P0 的解法，摘要）

1. **把「合」做成节点采集器（一箭四雕，最高优先）**：一格提交 ①我做了 ②我想到 ③脑子里第一句话 → 一次交给他 → 即时见证 +「今天到这里」。**同时解决**每日两问落点、第③问界面、L5 采集、邮件唤回的归因。
2. **认知层三指标零成本化**：L5＝第③问（可跳过）｜L4＝AI 识别后**一键记、可撤销**｜M＝**不新增交互**，定义"掉回旧模式"＝第③问回到旧句式，记进 `threads[].evidence` 加 `kind:'regress'`（**零新表**）。**不能为采集给用户加第三个日常任务。**
3. **6 节点闭环**：邮件（带那个节点的问题）+ 一格提交 → `events.node_verdict` → 三态判断 → 提前收官。
4. **「悬着的东西」清单**（召回引擎的产品内一半）：可见、可点开、**不可清零**。
5. **首页「你上次留在这里」**（＝P3-4）。
6. **触达的"信"再进一步**：D66/D90 附**带走的物件**（他自己的原话拼的，不给结论）。
7. **多书的区域要给"不同的世界"**（独立意象/色调）。
8. **上线前置**：见 P1 全部。
