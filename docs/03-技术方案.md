## 4. 身份与档案

- `identity.ts`：`getKey()` → 登录用户用 `user.id`；游客用 saas-kit 匿名 cookie（IP 兜底），key 前缀 `g:` / `u:` 区分。注册后迁移：`UPDATE ... SET user_key=u:xxx WHERE user_key=g:xxx`（同事务换主键）
- 恢复码：12 位（去易混字符 `23456789ABCDEFGHJKMNPQRSTUVWXYZ`），生成时存 `sha256(salt+code)`；`POST /api/me/recovery` 验证 = 账号级 5 次/时 + IP 级 20 次/时 + 全局失败锁定
- 活跃足迹：任一动作（会话/微行动/日记）完成时 `total_active_days` 原子 +1（`last_active_date != today` 时），单条 UPDATE 带条件

## 5. LLM 上下文组装（P§6 优先级的落地）

`prompt.ts: buildChatContext({ locale, profile, stage, sessions })` 按优先级装配，token 预算内从低优先级开始裁剪：

```
1. 安全规则层（固定，四语版；危机协议见 §6；"内容由 AI 生成"声明）
2. pinned：用户禁忌/重要承诺（超预算也不裁）
3. 阶段引导：content/{locale}/journey/N.md 正文 + ai_stance
4. practices：content/practices/ 按 stage 过滤 → 中文原文注入 + 指令
   "以下为创造者的实践经验（原文中文），用 {locale} 转述其经验，标注为创造者观点"
5. 画像：spoken 原话引用 / 已确认脚本 / 底色 / moments
6. 开放 concerns
7. 最近 N 轮对话（chat_messages）
8. 远期 memories（预算有余才放）
```

- 初谈（onboarding_talk）单独 system：只深挖一个点、不建议不纠正，结束后产出 JSON（瞬间候选/脚本候选）供画像生成
- 画像生成：`POST /api/onboarding/portrait` 一次性生成四段 + 空泛标签禁令写进 system
- 记忆：会话结束（轮数上限/用户离开）触发同步轻摘要（1-2 句，同请求内完成）；详摘要走 Vercel 后台函数或下次会话前惰性补（MVP 用惰性，不上队列）

## 6. 安全层（P§8 的实现）

- `safety.ts`：两段式——① 关键词粗筛（每语言词表，`content/safety/{locale}.json`，git 管理）② 命中后 LLM 语义确认（低温度、仅分类：危机/家暴/无，不产生面向用户文本）。抽检集 `src/tests/safety-fixtures/{locale}.json` 进 CI
- 命中处理：对话流插入转介消息（该语言资源表 `content/safety/resources/{locale}.json`）+ `safety_events` 落一行 + 该会话后续 system 注入"稳定陪伴模式"（不深挖、不拉回任务）
- 覆盖入口：chat / journal（VIP 回应前）/ letters（回信前）/ calibrate 反馈
- 每语言抽检召回率达标才开该语言（P§1 语言开放策略的实现依据）

## 7. 配额落账（P§7"失败不扣"的实现）

```
POST /api/chat/sessions     → 建 session（quota_consumed=false），前端进入
POST /api/chat/[id] 消息流式 → AI 首条回复完成后：
  若 !quota_consumed → /api/quota/consume(kind=chat_session) + quota_consumed=true（同事务语义：先 consume 成功才置位）
  失败/中断 → 不落账，session 可重试
轮数上限 20：message_count ≥ 40（=20 轮）时 API 返回温和收尾提示
游客/免费/VIP 档位由 saas-kit quota 层判定；VIP 跳过 consume
```

## 11. 修订记录

### 2026-09-12 · M9

- 新增 `src/lib/stage.ts`（推进判定表 + `computeStageProgress`/`pendingStamps`）、`src/lib/evolution.ts`（portrait_versions 访问 + 基线/素材/提议纯函数 + 演进 prompt）、`src/lib/timeline.ts`（六源归并）；新路由 `POST /api/journey/advance`、`POST /api/portrait/evolve`（generate/dismiss，maxDuration=120，不消耗聊天配额）。
- **两个真库才暴露的坑（smoke-m9 抓到，已修）**：
  1. Neon HTTP 驱动把 timestamptz 解析成 JS `Date`——`String(row.x)` 得到 `"Fri Sep 11 2026 ..."` 这种无法回代 SQL、不能 `slice(0,10)` 的串。统一走 `db.ts` 新增的 `iso()`。
  2. neon sql tag 把 `${字符串}` 一律参数化：`SELECT ${SESSION_COLUMNS}` 实际执行 `SELECT $1`，返回整列垃圾行（owner 回看自己会话都 404）。列名清单必须写死字面量，已全部内联。
- smoke-m9 断言全部数据驱动（种子内容/href/DB 状态）：RSC flight payload 会把整份词典序列化进 HTML，grep 词典文案必假阳性；并发 generate 的败者对新基线返回 403 也是正确行为（真闸），不视为事故。

### 2026-09-12 · M9 修订：阶段进度从交互计数制改为认知/行为评估制

语义总纲（用户修正）：进度评估的是「用户当前表现出的认知与行为」实际所处的阶段——离核心价值「一辈子不愁钱的活法」已达成的进度——与产品内操作/交互次数没有严格关系。

- **删除**：`stage.ts` 的 `STAGE_CHECKS`/`pendingStamps`/`canAdvance`（机械计数判定）；journey 渲染补发印；`POST /api/journey/advance` 路由与 `AdvanceCard` 组件（404 验证留存）。`stage.ts` 重写为 `STAGE_LAMPS`（判定表：kind + labelKey + 中文 hint，阶段 1/2/3 各 3 盏）+ `computeStageProgress`（done = stamps 里有没有该 kind，**stamps 是点亮唯一真值**）。
- **新增** `src/lib/assess.ts`（镜像 evolution.ts 全部模式：读时现算提议闸 `shouldOfferAssess`（素材 ≥3 或 ≥14 天且有任意素材；冷却/锁/pending 30 天 TTL 各挡）+ `validateAssessment`（actualStage 限 [stage, stage+1] 整数、lamps 恰覆盖灯集、lit 必有 evidence、summary 10..800）+ `buildAssessMessages`（见证者 prompt：标尺=content 的 goal/advance_when，红线=证据禁编造/不评判不打分/无理财建议诊断）+ 原子抢锁 `claimAssessment`/`releaseAssessmentLock`/`saveAssessmentState`（JSONB `||` 合并）+ `gatherAssessMaterial`）；新路由 `POST /api/journey/assess`（action=generate/confirm/advance/dismiss；generate 先过闸后抢锁，validate 失败重试一次仍败则清锁 502 fail-safe；advance 服务端复算 `pending.actualStage > stage` 防绕；maxDuration=120，不耗聊天配额）；新组件 `AssessCard`（offer/review 双模式）；journey 页确认过的灯下展示依据（confirmed 里的 evidence）。
- **数据**：`growth_profiles` 加 `stage_assessment JSONB DEFAULT '{}'`（行内 → 导出/删除/游客迁移级联天然覆盖）；导出路由为显式字段枚举，补 `stamps` + `assessment` 两字段（评估依据属用户内容，可携权带走）。
- **LLM 长度规则必须语言感知（smoke 真库抓到的 502 根因）**：中文按字数、英文按词数——glm-5.3-flash 被语言钉死行强制英文输出时，prompt 写「80-200 字」会产出 551 字符的 summary 撞上 400 字符校验上限。修复：`buildAssessMessages` 长度规则按 locale 分叉（en 60-120 words / 80 words or fewer / 30 words or fewer），`validateAssessment` 上限 800 作为结构边界（防失控，风格长度交给 prompt）；evidence/nextHint 截断 300。测试锚点：700 字符过 / 801 拒。
- **全局进度条**：新 server 组件 `JourneyProgressBar`，挂在 layout 的 sticky 底部导航容器内（导航上方）→ 全部页面固定可见、零页面改动；layout 加 `resolveIdentity+getProfile`（try/catch 失败按 null 处理，绝不因进度条挂掉）并 `force-dynamic`。内容：左「阶段 n · 标题」（阶段 4「活法中」），右四段（已过=实心；当前=按 litCount/灯数 填充；未至=line 色；阶段 4 当前=accent/40 无刻度）；整条是包 /journey 的 Link。
- **并发语义备注**：generate 先过闸（shouldOfferAssess）后抢锁（claimAssessment），败者过闸时读到的 generatingAt 已置位 → 得 403 `assess_not_proposed` 而非 429；smoke 断言「恰一次真生成」接受 429/403 任一形态。
