## 4. 身份与档案

- `identity.ts`：`getKey()` → 登录用户用 `user.id`；游客用 saas-kit 匿名 cookie（IP 兜底），key 前缀 `g:` / `u:` 区分。注册后迁移：`UPDATE ... SET user_key=u:xxx WHERE user_key=g:xxx`（同事务换主键）
- 恢复码：12 位（去易混字符 `23456789ABCDEFGHJKMNPQRSTUVWXYZ`），生成时存 `sha256(salt+code)`；`POST /api/me/recovery` 验证 = 账号级 5 次/时 + IP 级 20 次/时 + 全局失败锁定
- 活跃足迹：任一动作（会话/微行动/日记）完成时 `total_active_days` 原子 +1（`last_active_date != today` 时），单条 UPDATE 带条件

## 5. LLM 上下文组装（P§6 优先级的落地）

`prompt.ts: buildChatContext({ locale, profile, stage, sessions })` 按优先级装配，token 预算内从低优先级开始裁剪：

```
1. 安全规则层（固定，四语版；危机协议见 §6；"内容由 AI 生成"声明）
2. pinned：用户禁忌/重要承诺（超预算也不裁）
3. 阶段引导：content/{locale}/journey/N.md 正文 + ai_stance
4. practices：content/practices/ 按 stage 过滤 → 中文原文注入 + 指令
   "以下为创造者的实践经验（原文中文），用 {locale} 转述其经验，标注为创造者观点"
5. 画像：spoken 原话引用 / 已确认脚本 / 底色 / moments
6. 开放 concerns
7. 最近 N 轮对话（chat_messages）
8. 远期 memories（预算有余才放）
```

- 初谈（onboarding_talk）单独 system：只深挖一个点、不建议不纠正，结束后产出 JSON（瞬间候选/脚本候选）供画像生成
- 画像生成：`POST /api/onboarding/portrait` 一次性生成四段 + 空泛标签禁令写进 system
- 记忆：会话结束（轮数上限/用户离开）触发同步轻摘要（1-2 句，同请求内完成）；详摘要走 Vercel 后台函数或下次会话前惰性补（MVP 用惰性，不上队列）

## 6. 安全层（P§8 的实现）

- `safety.ts`：两段式——① 关键词粗筛（每语言词表，`content/safety/{locale}.json`，git 管理）② 命中后 LLM 语义确认（低温度、仅分类：危机/家暴/无，不产生面向用户文本）。抽检集 `src/tests/safety-fixtures/{locale}.json` 进 CI
- 命中处理：对话流插入转介消息（该语言资源表 `content/safety/resources/{locale}.json`）+ `safety_events` 落一行 + 该会话后续 system 注入"稳定陪伴模式"（不深挖、不拉回任务）
- 覆盖入口：chat / journal（VIP 回应前）/ letters（回信前）/ calibrate 反馈
- 每语言抽检召回率达标才开该语言（P§1 语言开放策略的实现依据）

## 7. 配额落账（P§7"失败不扣"的实现）

```
POST /api/chat/sessions     → 建 session（quota_consumed=false），前端进入
POST /api/chat/[id] 消息流式 → AI 首条回复完成后：
  若 !quota_consumed → /api/quota/consume(kind=chat_session) + quota_consumed=true（同事务语义：先 consume 成功才置位）
  失败/中断 → 不落账，session 可重试
轮数上限 20：message_count ≥ 40（=20 轮）时 API 返回温和收尾提示
游客/免费/VIP 档位由 saas-kit quota 层判定；VIP 跳过 consume
```

### 2026-09-13 · 以图为中心：StageLampChart 雷达灯图 + 行动按钮化（产品口径见 docs/02 §12）

- **几何纯函数** `stage.ts` `lampChartPoints(n)`：单位圆顶点均布（顶部起始顺时针；3=三角、2=上下两点、0=[]），渲染层乘视窗尺寸；单测断言圆上距离与 120° 角距。
- **新 client 组件** `StageLampChart`：SVG（viewBox 220×200，圆心 110/100 半径 64）——虚线参考圈（标准）+ 点亮顶点 polygon（fillOpacity 0.12，≥2 盏亮才连形）+ 节点（亮=实心 accent+光晕、未亮=空心 paper+描边）；SVG 节点与图下灯行共用一个 `open` state（默认展开第一盏未亮）。灯行展开：未亮=hint+`data-lamp-cta` Link（chat），已亮=evidenceLead+依据。行动按钮组 `data-action-cta={i}` 每条 Link → chat。

### 2026-09-13 · 走过的段也展示灯 + 报告阶段标注（产品口径见 docs/02 §12）

真实推进第一次发生后暴露的呈现缺口：journey 页 stages.map 只展开当前段（`current &&` 守卫），推进后走过段的灯/依据/心印/报告全部消失。修订（journey/page.tsx 单文件 + i18n）：

- **stProgress 按段现算**：`computeStageProgress(s.id, profile)` 下沉进 map（原顶层只算当前段）；顶层 `progress` 变量删除。
- **走过段灯块**（`walked && stProgress.checks.length > 0`）：计数恒 `n/n`、三盏灯全 ●（走过即整段点亮——推进即评估结论，呈现层灯不灭成立）；依据走 `confirmedEvidence.get(kind)`（最近一次确认评估还覆盖该段时显示），不渲染 hint 与 waiting 行。

  2. neon sql tag 把 `${字符串}` 一律参数化：`SELECT ${SESSION_COLUMNS}` 实际执行 `SELECT $1`，返回整列垃圾行（owner 回看自己会话都 404）。列名清单必须写死字面量，已全部内联。
- smoke-m9 断言全部数据驱动（种子内容/href/DB 状态）：RSC flight payload 会把整份词典序列化进 HTML，grep 词典文案必假阳性；并发 generate 的败者对新基线返回 403 也是正确行为（真闸），不视为事故。
