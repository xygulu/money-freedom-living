## 1. 产品全景与信息架构

产品 = **一间只属于你的、关于钱的房间**。移动优先（微信内打开为主场景），底部 Tab 四个：

```
落地页 /                     未注册用户入口
  └─ /onboarding            金钱关系体检（问卷 → AI 初谈 → 画像 → 校准）
      └─ /portrait          你的金钱画像（起点，可校准）

已进入用户（底部 Tab）：
┌──────────────────────────────────────────┐
│   旅程        对话        日记       我的   │
│ /journey     /chat     /journal     /me   │
└──────────────────────────────────────────┘

/journey    旅程主页：今日三件事 + 阶段路标 + 当前位置
/chat       AI 陪伴对话（产品核心）
/journal    金钱心事（日记 + VIP AI 回应）
/me         档案入口、VIP 订阅 /vip、恢复码、设置
/timeline   成长足迹（v1.5，从 /journey 进入）
```

**MVP 页面清单**：`/`、`/onboarding`、`/portrait`、`/journey`、`/chat`、`/journal`、`/vip`、`/me`。`/timeline` 与信件的完整仪式感放 v1.5。

**市场与客户端路线（2026-09-11 更新：面向海外用户）**：产品通过 **Creem 收款，面向国外用户**；界面四语：**英语 / 简体中文 / 繁体中文 / 日语**（内容层结构见 §10）。**简体中文面向海外华语用户**（新加坡/马来西亚/海外华人/留学生），不面向中国大陆境内——若未来进入中国大陆，另行评估备案与 AI 合规；语言选择器写"简体中文"，不标国别。MVP = 国际 Web（移动浏览器优先）。**Web Push 在海外完全可用**（Chrome/Safari/ iOS 16.4+ PWA），主动触达从"不可行"变为"可行"，安排在 **v1.5**（MVP 仍先聚焦核心体验，留存靠产品内机制）。后续 **iOS APP 走国际区**上架：个人开发者账号 + IAP 即可，无中国区备案负担（条件见 §9）；后端 API 按"多客户端"设计，届时只新增 Expo 客户端，后端不变。

**上线前 Go/No-Go 里程碑（P0，写代码前先排期）**：

1. **LLM 多语言盲测**：en / ja 心理陪伴对话自然度盲测（日语需母语者评分）——**语言开放范围由此决定**，不达标则该语言不开放，宁少开、不开烂；不达标时在现有 Anthropic 兼容网关上加 provider（切换成本低，但切换后需重测）
2. **语言开放策略**：MVP 语言选择器四项可见，**ja / zh-TW 标注 Coming soon 锁定**，实际开放 en + zh-CN；转正条件 = LLM 盲测通过 + 危机识别抽检通过（§8）+ 内容母语校对完成（§10），三项齐备即解锁
3. **免费单位经济测算**：活跃免费用户月成本 vs VIP 转化率 × 客单价；调节旋钮 = 会话轮上限、免费/VIP 模型分级、记忆摘要频率（见 §7）
4. **Creem 可用地区与税务处理**（VAT/GST）确认
5. 产品**英文名**（品牌名；代号 money-freedom-living 可先作域名）

设计基调：暖、静、私密。**没有排行榜、没有社交元素、没有分数仪表盘。**

**进度呈现纪律**（对"无进度焦虑"基调的具体化）：

- 阶段路标显示"你在这里"，**不显示百分比、不显示"已完成 X/4"、不显示落后**
- 阶段推进 = **AI 提议 + 用户确认**；用户可回退、可反复、可暂停，暂停不标记失败
- 心印是**纪念**（走到的见证），不是徽章收集；没有"差一枚"的提示
- "说不清自己有没有变化"是合法回答，不逼用户正向

## 2. 首次会话流程（效果保证的第一现场）

目标：**10 分钟内至少 2-3 处精准说中**（"它说中了我"），画像作为第一版交给用户校准——不追求一次穷尽，追求精准引用。

```
落地页 CTA「看看你和钱的关系」
   ↓
① 问卷（6 题，2 分钟）→ ② AI 初谈（3-5 轮）→ ③「我听到的是…」确认
   → ④ 生成画像 v1 → ⑤ 校准（说中了 / 不太像，可改）→ /portrait
```

### ① 问卷：收集"具体的事"，不是量表分数

选择题为主 + 2 道开放题，每题都落到档案字段：

| # | 问题 | 形式 | 进档案的字段 |
|---|---|---|---|
| 1 | 最近一次为自己买"纯粹想要"的东西，是什么时候？ | 四选一（这周/这个月/想不起来/不敢想）+ 可补充 | specific_moments |
| 2 | 打开余额的时候，你的第一感觉是？ | 四选一（平静/逃避不想看/心慌/无所谓反正不够） | money_feeling |
| 3 | 小时候家里，关于钱你印象最深的一句话或一个画面？ | **开放题（核心题）** | script_source |
| 4 | 钱到账的那天（发薪日），你的第一个动作是？ | 四选一（先还账/先存起来/犒劳自己/没什么感觉） | payday_habit |
| 5 | 你最羡慕什么样的人和钱的关系？ | 四选一（松弛不纠结/敢花/很会赚/不被钱支配） | aspiration |
| 6 | 最近一次为钱心慌或内疚，是什么时候、因为什么？ | **开放题（核心题）** | concerns 种子 |

### ② AI 初谈：追问一个点，深挖而不是重复问

AI 读问卷答案，挑**最有情绪重量的一处**追问 3-5 轮。要求：

- 只深挖一个点，让用户感到"它在认真听"而非"走流程"
- 全程不给建议、不安慰、不纠正——只反映和好奇
- 不够素材的地方宁可少写，**禁止编造**（画像里没有的内容不出现）

### ③ 「我听到的是…」确认（生成画像前）

AI 用 3-5 句话复述它听到的关键点，用户确认/补充。这一步同时是**素材校验**：AI 拿不准的地方在这里问清，而不是在画像里猜。

### ④⑤ 画像生成与校准

画像 v1 生成后，页面上每一段都可反馈：**"说中了" / "不太像"**（可写一句修正）。校准结果写回档案——"不太像"的内容 AI 不再使用，并在下次引用时避免。画像即可继续编辑微调。

## 3. 金钱画像（产品的灵魂物件）

**用文字，不用分数；引用与推断分层，推断永远标注。**

```
┌────────────────────────────────────┐
│         你的金钱画像                 │
│                                    │
│  【你说过的】                        │
│  "放进购物车，过两天再默默删掉"       │
│  "我妈说，咱家不配。"                │
│  （2-4 条用户原话的直接引用）          │
│                                    │
│  【你的金钱底色】                    │
│  你不是没有钱，是花钱那一刻总有个     │
│  声音说"再省一点"。……（100-200 字，  │
│  第二人称，围绕上面那些原话展开）      │
│                                    │
│  【你和钱的三个瞬间】                │
│  · 小时候听到"咱家不配"的那个傍晚     │
│  · 上个月退掉那双鞋时的松了口气       │
│  · 发薪日先还花呗的长舒一口气         │
│                                    │
│  【我听到的可能】                    │
│  也许有一条很旧的脚本在你心里：       │
│  "不配享受"。它可能来自很久以前，      │
│  不一定是现在的真相。——像吗？         │
│      [ 像 ]  [ 不太像 ]             │
│                                    │
│  【给未来的你】                      │
│  2026 年 9 月 11 日，你从这里出发。   │
│                                    │
│      [ 和它聊聊 ]  （→ /chat）      │
└────────────────────────────────────┘
```

设计规则：

- **你说过的**：用户原话直接引用。这是说中感的来源——允许暂时只有 1-2 条，不硬凑
- **金钱底色**：第二人称、围绕原话展开；**每句话必须能追溯到用户说过的话**，禁止空泛性格标签
- **三个瞬间**：从问卷和初谈提取的 3 个具体场景（不足 3 个就写几个）——这是后续**回访机制的数据源**，作为结构化字段单独存，永不参与摘要滚动
- **我听到的可能**：AI 推断层，**必须用"也许/可能"措辞，旧脚本最多 1 条，必须经用户确认（像/不太像）**。确认"像"后这条脚本才进入 AI 的长期工作记忆
- **给未来的你**：画像页自动成为时间线的第一个节点
- 示例中的日期、数字仅为示意；**日期/数字/货币格式一律走 i18n 格式化层**，不硬编码任何语言格式

画像不是一次性的：阶段毕业时更新版本，v1.5 做前后对比。

## 4. 四阶段旅程设计

每阶段在 `content/journey/` 有一个定义文件（schema 见 §10），包含：目标、练习、AI 姿态、可观察的推进标志、仪式。以下为 v1 内容设计：

> **v1.1 注（阶段进度的语义修正）**：下文各阶段的「推进标志」是 AI 阶段评估所用的**观察标尺**（认知/行为描述），**不是机械触发条件**——进度评估的是用户当前表现出的认知与行为实际所处的阶段（离核心价值「一辈子不愁钱的活法」达成的进度），与产品内操作、交互次数没有严格关系。机制详见 §12 修订记录「M9 修订：阶段进度改为认知/行为评估制」。

### 阶段进度评估标准（评估制的完整口径）

**判定表**：全产品只有 8 盏灯（阶段 1/2/3 各 3/3/2 盏，阶段 4 无灯无终点线），单一真值源是代码里的灯判定表（`src/lib/stage.ts` 的 STAGE_LAMPS）；灯只有「亮/不亮 + 依据」两种状态，不做部分点亮，深度交给诊断文字。

**判定的是程度，不是动作（2026-09-13 程度制修订）**：每盏灯 = 本阶段离「一辈子不愁钱的活法」应达程度的一个切面——判定的是**状态到达了没有**，「他做过什么」只是判断程度的证据，不是标准本身。灯名四语与 8 条点亮标准全部重写为程度句式（如「允许过自己」，而不是「完成一次不配的小事」）；评估 prompt 加红线「判定程度，不数动作：不要核对任务清单、不要数次数」；content 各阶段 advance_when 同步改写为程度句式（同一张标尺喂给评估 LLM）。用户旅程页看到的灯名、标准、评估用的标尺，是同一份文字。

**证据规则**：评估素材 = 这段时间的对话摘要、日记、微行动与感受、信、画像修正，**加上体检画像本身**（问卷原话、说过的话、和钱的瞬间、金钱底色、旧脚本）——体检画像不参与「基线之后」过滤（它是当前态的自述），且旧脚本必须连同用户状态一起陈述（候选不得当作已认可，否认本身也是态度）。每盏点亮的灯必须引用原话或具体的事，禁止编造；没看到就如实说没看到；画像是自述，判断「他现在的样子」时要与这段时间的言行放在一起看。

**评估人与确认权**：AI 评估，用户确认——AI 提议 + 用户点头才生成；结果「记下现在的样子 / 走进下一阶段 / 不是这样的」三选一，「不是这样的」14 天冷却，无惩罚不追问。

**首评时机**：**体检完即首评**——从未确认过任何评估的用户，体检画像本身就是阶段 1 三盏灯的直接证据，不受「新素材 ≥3 条」限制；首评确认之后，素材基线从确认时刻重新起算。

**评估报告四件套**（评估不是「做了什么」的清单，是一份诊断）：①**他在哪**——位置 + 灯 + 依据；②**为什么是这里**——用书的机制框架（早期场景→金钱底色→旧脚本→现在的模式）解释成因，引用他的原话，只解释心理机制，不做医疗诊断、不用病症词汇、不评判人格；③**离「一辈子不愁钱的活法」还有多远**——路标式描述，不恐吓、不许诺、不给数字承诺、不制造焦虑；④**下一步可以做什么**——2-3 个对齐本阶段练习方法的具体小步（观察任务/微实验/允许清单/改写台词），今天就能开始，不出现任何理财建议。确认后的报告常驻旅程页。

**呈现（心印刻度）**：全局进度条 = 「阶段 n · 标题 + 四段刻度 + 当前阶段已点亮 x/y 盏」——各段按该段**实际点亮**的灯比例填充，无百分比、无「还差多少到下一阶段」；没有评估过的阶段不造假进度；阶段 4 整段淡色常亮、不渲染计数。

**只增不减**：灯不熄灭、阶段不倒退、确认过的报告不消失；「不是这样的」只推迟不扣减。

### 阶段 1 · 看见（约 2 周）

- **目标**：如实地看见自己和钱的关系，不评判
- **练习**：① 完成体检与画像 ② 金钱记忆回溯（和 AI 聊最早的金钱记忆）③ 一周观察任务（"这周留意你什么时刻会想起钱"，回来告诉它）
- **AI 姿态**：倾听者、镜子。**只反映，不建议、不纠正、不急着正向。** 红线单独写：不劝、不夸、不总结人生（内容文件 `ai_stance` 落地）
- **推进标志（可观察行为，AI 提议 + 用户确认）**：画像已校准 + 用户用自己的话提到过三个瞬间 + 已确认一条"我听到的可能"
- **仪式**：「给现在的自己」第一封信（AI 温柔回信）

### 阶段 2 · 松动（约 3 周）

- **目标**：看见脚本从哪来；情绪被看见，松动就开始
- **练习**：① 童年金钱场景重访（陪 AI 重新走进那个画面；**安全边界见 §8，AI 保持轻触不深挖创伤**）② **写给钱的一封信**（核心仪式，可以写愤怒、委屈、抱歉）。**信的 AI 回信原则：承接情绪、确认收到，但不分析、不解读、不给建议**——保护"把信交给钱"的仪式感 ③ "我一直不敢为自己做的那些小事"清单
- **AI 姿态**：陪伴者、见证者。接住情绪，**不催用户"走出来"**
- **推进标志**：完成写给钱的信，且用户选择封存或留着（怎么处理都算完成）
- **仪式**：心印「看见来处」

### 阶段 3 · 练习（约 4 周，弹性最长）

- **目标**：用一个个小实验，建立和钱的新相处方式
- **练习**：① 允许清单（列出一直不敢为自己花的钱，从小额开始）② 每天一个微小实验（为自己花一笔纯粹开心的钱 / 享受一件免费的美好 / 对一笔支出说"值得"）③ 实验后回来记录感受，AI 接住每一次。**实验记录入口（开发依据）**：`/journey` 微行动卡上"完成实验 + 一句话感受"直接写入 `experiments[]`；对话中用户提及实验时由 AI 补记——写入路径在 docs/03 细化
- **AI 姿态**：教练 + 啦啦队。庆祝微小的突破；回访画像里的三个瞬间——"你说发薪日会心慌，这次发薪日呢？"
- **推进标志**：完成 ≥7 次实验记录 + 用户自评"有变化 / 没变化 / 说不清"（**三种回答都算有效推进，"说不清"不挡路**）
- **仪式**：心印「练习松弛」+ 画像 v2

### 阶段 4 · 活法（长期，v1.5 开启）

- **MVP 中的呈现**：入口在旅程地图上**可见，点击进入预告页**——写清阶段 4 是什么、计划何时开启、现在可以先做什么，并提供**"开启时通知我"邮箱收集**（预告不是死胡同，同时也是召回名单）
- **目标**：把松弛过成日常，定义属于自己的"不愁钱"
- **练习（主题包，滚动更新）**：① 写下"我的不愁钱定义"（和多少钱无关）② 活法清单（日常化小实践，如每月一天"随心日"）③（可选）"收入与自由"的生活反思——**全产品唯一碰数字的地方：只做感受与选择反思，不做任何财务规划（红线见 §8）**
- **AI 姿态**：陪练。话题从疗愈转向生活，定期回访活法践行
- **无"毕业"**：改为**周期回顾**——每 4-6 周一次"这阵子和钱处得怎么样"（画像版本可更新）；主题包持续上新是长期价值的来源，不靠"永远不结束"

## 5. 每日节奏

用户每天打开 `/journey`，看到三件事——**全部可跳过，跳过不打断足迹，无未完成红点**：

1. **今日一签**：从 `content/daily/` 原创心法池按日取（按当前阶段适配：**阶段 1 用观察提问型**（"这周你什么时候会想起钱？"），不用鼓励金句；阶段 3-4 才用练习与活法型）
2. **今日微行动**：按当前阶段的练习生成，也可换成"随便聊聊"或"今天只看看签"
3. **陪伴对话**：进入 `/chat`（消耗会话配额，见 §7）

对话开场由 AI 依据档案决定（优先级从高到低）：昨天微行动的回应 → 回访钩子（三个瞬间/开放中的困扰）→ 当前阶段引导 → 自由聊。用户随时可以完全不接引导。

**微行动的「被看见」闭环（M10，读→做→证→叙）**：外部机制评审的核心洞察——坚持的本质不是激励话术，是「我做这件事有人看见了」。落地为三条，全部不越温馨红线：

1. **即时见证回应**：微行动提交后**当场**给一句收条体回应（镜像信件回信红线：承接、见证、不分析不评判、不追问下一步），免费可用——「记录当天必被回应」是机制唯一不能省的一环，不再等下次对话的开场白。
2. **0 元替代版**：每个涉钱的微行动在 content 里配一个 0 元替代动作——想省钱的人恰恰是最需要的人，不配 0 元版等于把他们挡在门外。
3. **被看见但不追问**：产品永不主动追问「今天你做了吗」，无打卡、无断签召回（红线承 §8 与 §12 已否决项）；掉队与断点只进内部数据（§11 机制验证仪表），绝不变回打扰。用户自选的温和提醒（默认关）列 v1.5 Web Push 规划。

**周期情绪锚点**：发薪日因国家/公司而异（日本 25 日、欧美常见双周薪）——onboarding 问卷追加一题**设定用户自己的发薪日/发薪周期**（每月某日 / 每两周 / 每周 / 不确定）。**默认不猜：跳过就不显示锚点**——猜"月底"会让用户觉得"它不懂我"；锚点文案本地化，不直译"发薪日"。用户打开产品时，旅程页在锚点日呈现"今天是发薪日，这个月和钱处得怎么样？"（被动感知）；**Web Push 上线后（v1.5）变主动**。

**暂停与归来**：用户暂停任意时长后回来，旅程页给一句"欢迎回来，它还在"——不追责、不问为什么没来、不显示中断天数。

## 6. AI 成长档案（机制的地基）

### 数据结构（逻辑字段，物理表结构见 docs/03）

```
growth_profile
├── identity            user_id 或游客匿名 key（saas-kit 同款解析）+ 恢复码
├── portrait            jsonb {你说过的话[], 底色, 三个瞬间[], 我听到的可能(待确认/已确认/已否决),
│                              给未来的你, version, 校准记录[]}
├── concerns[]          具体困扰池 {内容, 状态: 开放/松动/化解, 来源时刻}
├── stage               1-4 当前阶段 + stage_started_at + 已确认的推进记录
├── memories[]          关键对话摘要（带日期，滚动合并）
├── pinned[]            【结构化，不参与滚动】重要承诺 / 未完成话题 / 用户禁忌
├── experiments[]       阶段 3 实验记录 {日期, 做了什么, 感受}
├── letters[]           信 {阶段, 内容, 状态: 留着/封存/已开, AI 回信}
├── stamps[]            心印 {类型, 获得时间}
└── total_active_days   累计足迹（不是连续 streak，跳过不断）
```

### 记忆机制（双层摘要，防"它不记得"）

- **同步轻摘要**：对话结束立刻写入 1-2 句关键点（下次对话立即可用）
- **异步详摘要**：后台生成完整摘要追加进 `memories`；超上限时只滚动合并**旧**的 memories 条目
- 三个瞬间、concerns、pinned 是结构化字段，**永不参与滚动合并**
- **上下文组装（带 token 预算与优先级）**：`安全规则` > `pinned（用户禁忌/重要承诺/未完成话题）` > `当前阶段引导语 + 创造者实践经验` > `画像（含已确认脚本）` > `开放中的 concerns` > `最近对话轮次` > `远期 memories`——禁忌与承诺高于一切内容层，防止 AI 冒犯用户

## 7. 配额与 VIP 门禁

原则：**旅程内容对所有人开放，VIP 卖的是更深、更久的陪伴**。免费用户慢走能走完全程（配额自然限速），没有任何内容墙。

| 能力 | 游客 | 免费 | VIP |
|---|---|---|---|
| 体检 + 画像 + 校准 | ✅ | ✅ | ✅ |
| 阶段 1-3 完整内容与练习 | ✅ | ✅ | ✅ |
| 阶段 4（v1.5 开启；MVP 中入口可见并显示"即将开启"预告） | — | — | ✅ |
| 陪伴对话 | 每日 1 会话 | 每日 3 会话 | 无限 |
| 信件 AI 回信 | ✅ | ✅ | ✅ |
| 日记的 AI 回应 | — | — | ✅ |
| 画像 v2 与前后对比 | — | — | ✅ |
| 周期回顾深度版（每 4-6 周） | — | — | ✅ |
| 阶段 4 主题包（独家/抢先） | — | — | ✅ |
| 更长记忆窗口 | — | — | ✅ |
| 更优对话模型（更细腻的对话质感） | — | — | ✅ |
| 阶段深度报告（毕业时生成） | — | — | ✅ |

**付费墙触发点（soft gate，全产品仅此四处，之外不出现任何推销）**：① 当日会话用完时（"今天先到这里，VIP 随时继续"）② 日记写完想被回应时 ③ 阶段毕业想看深度报告时 ④ 阶段 4 主题包入口（**MVP 中随阶段 4 未开启而暂不存在，实际为三处**）。不打断旅程、不弹窗轰炸。

**成本旋钮（保护"无内容墙"承诺下的单位经济）**：免费/VIP 分级使用不同档位模型；会话轮上限与记忆摘要频率为可调参数。上线前完成免费用户单位经济测算（§1 里程碑 3）。

**配额精确定义**（开发依据）：

- **1 次 = 一次对话会话**：进入 `/chat` 发起对话算 1 次；会话内上限 20 轮（用户一句 + AI 一句），到上限温和收尾（"今天先到这里，明天它还在"）
- **首次流程不占配额**：问卷、AI 初谈、"我听到的是"、画像生成、画像校准全部免费不扣
- **失败不扣**：模型/网络失败、会话内重试、重新生成均不消耗配额（落账以"成功产生 AI 首条回复"为准；实现细节见 docs/03）
- **重玩纪律**：任何"重新生成/再聊一次"入口同样过门禁检查（哄哄踩过的坑，纪律条款）
- **游客档案保护**：游客身份用 saas-kit 匿名 cookie；**Safari ITP 会清除 7 天未交互站点的存储**（海外用户 Safari 占比高）——`/me` 提供 **12 位恢复码**（字母数字、剔除易混字符），服务端**只存加盐哈希**、校验防护 = 账号级限速 + IP 级限速 + 全局失败锁定 + 异常告警，另备**邮箱验证**作为码丢失的找回路径；换设备/存储被清可凭码找回档案，并在关键节点（画像生成后）引导邮箱注册，档案无缝继承
- 门禁统一走 saas-kit `/api/quota/consume`（`kind=chat_session`）

## 8. 安全与边界（P0，先于一切功能）

金钱话题会触达真实创伤。AI 是**陪伴者，不是治疗师**；以下为不可协商的底线。

### 8.1 危机识别与转介

- **覆盖所有用户文本入口**：对话、日记、信件、画像校准反馈——不只对话流（在隐私政策与 AI 声明中如实告知："为保护你的安全，我们会检查所有输入中的危机信号"）
- 识别**危机信号**（自伤、自杀意念、家暴、被虐待等关键词与语义）——命中时：AI 以**用户的界面语言**停下陪伴话术，明确表达关心，**提供该语言对应地区的转介资源**（资源表上线前逐条核实；家暴等按类目区分）：
  - 英语：988（美）+ 当地危机热线国际目录 + 家暴热线
  - 日语：いのちの電話 0570-783-556、#いのちSOS
  - 简体/繁体：按用户所在地展示对应热线
  - 通用：建议联系信任的人 / 线下专业帮助
- **命中后不冷落用户**：转为稳定陪伴 + 转介，不继续深挖、不强行拉回练习任务
- **危机识别按语言分别验证**：每语言独立抽检集，**召回优先、误报可接受**；日语单独构建抽检集（「消えたい」类隐晦表达是难点，直译关键词会漏检）——**某语言危机识别不达标，该语言不开放**（与 §1 语言开放策略联动）
- 命中后该会话记录打标记，概不继续深挖创伤话题
- 明确免责声明（落地页与首次对话内出现一次）：本产品不提供心理治疗、医学诊断，也不能替代专业帮助

### 8.2 内容红线（写入所有阶段 system prompt 的固定层）

- 不提供投资、税务、法律建议；**不鼓励任何借贷、消费、投资决策**（阶段 3"为自己花钱"的实验永远由用户自主决定，AI 只谈感受不谈该不该买）
- 阶段 4"收入与自由"只做生活反思，**不做财务规划、不给数字建议**
- 不诊断心理疾病、不给用户贴病症标签、不承诺疗效
- 不在未经用户提起时主动深挖童年创伤；用户表现出强烈痛苦时，回到陪伴而非"继续完成练习"

### 8.3 用户准入

- 18+（落地页与 onboarding 声明）；未成年人需监护人同意（MVP 直接 18+ 门槛）

## 10. 内容层规范（共创通道）

内容与代码分离，全部 git 管理。**用户的实践经验写进 `practices/` 即生效**。

### 多语言结构（四语：en / zh-CN / zh-TW / ja）

```
content/
├── en/            # 按语言分目录：journey/ + daily/
├── zh-CN/
├── zh-TW/
├── ja/
└── practices/     # ★ 中文单一事实源，不按语言分
```

- **journey / daily**：每语言一份内容文件；文件名与 frontmatter 结构完全一致，语言间通过文件路径对应
- **practices（创造者笔记）保持中文单一事实源**：创造者只用中文书写；AI 组装上下文时以**用户的界面语言转述**"创造者的经验"（system prompt 注明此要求）——共创通道不因多语言而增加创造者的书写负担
- **书名/作者本地化**：日语内容用原书名《一生お金に困らない生き方》与"心屋仁之助"原名原生呈现；简体用《一辈子不愁钱的活法》；繁体用当地版书名；英语用译名+罗马字作者名
- **翻译流程**：深度内容（journey/一签）en + zh-CN 由创造者校对定稿为**质量标杆**；en / ja 各找一位**母语校对**（至少校对阶段 1——创造者中文为主，en/ja 自校能力有限）；ja + zh-TW 由 AI 从标杆翻译起草、母语校对通过后转正——**转正前该语言不开放**（见 §1 语言开放策略）

### `content/journey/N-阶段名.md`

```yaml
---
id: 3
title: 练习
goal: 用小实验建立和钱的新相处方式
weeks: 4            # 预计时长（弹性参考值，非 deadline）
exercises:          # 供每日微行动生成
  - 允许清单
  - 每日一个小实验
ai_stance:
  do: [庆祝微小的突破, 回访画像瞬间]
  dont: [给理财建议, 用分数衡量用户, 催用户走出情绪]
advance_when:       # 可观察行为清单（AI 提议推进的依据）
  - 完成 7 次实验记录
  - 用户自评（有变化/没变化/说不清 均可）
ritual: 心印「练习松弛」+ 画像 v2
---
（正文：这个阶段的引导语、话术示例、红线与注意事项——AI system prompt 的直接原料）
```

### `content/daily/`（今日一签素材池）

**原创短心法（受书的理念启发自写，不引用原书文字）**——商业产品直接摘录在版书摘有版权风险；如后续获得授权或采用公版内容再放开。**MVP 备量 ≥90 条**（90 天不重复，配合不重复抽取逻辑）。每条：`{text, type: 观察/练习/活法, stages: [适配阶段], reflection}`

### `content/practices/`（创造者实践经验笔记）

**写入权限仅创造者/管理员**（git 仓库权限控制），普通用户不可写——这也是注入安全的边界：进入 system prompt 的笔记全部来自受信仓库，且安全规则优先级永远高于笔记内容（见 §6 组装顺序）。

frontmatter 要求 `date` + `type: fact | opinion`（事实/观点标注，AI 组装时据此措辞）+ 可选 `tags` + `stage`，正文自由书写。注入规则：

- 按**当前阶段相关度过滤**（`stage` 标签匹配），不是全量裸注入
- 笔记需区分**事实（我做了什么、发生了什么）与观点（我认为…）**——写作约定写在目录 README 里；AI 组装时观点性内容标注为"创造者的经验"
- 与阶段引导语冲突时，**阶段文件的 `ai_stance` 优先**，笔记作为补充视角

### 命题标签与动作记录规范（M10）

跨书抽象层（docs/01 §7「命题索引」）在内容层的落点：

- **命题标签**：journey 练习、一签、practices 笔记均可选标 `topics`，取值限六命题：`self-worth`（我不配）/ `parents`（和父母的关系）/ `inner-turmoil`（情绪与内耗）/ `boundaries`（关系与边界）/ `money-safety`（金钱与安全感）/ `allowing`（允许自己）。MVP 只用于 practices 过滤与评估诊断的归属参考，不做面向用户的分类导航。
- **0 元替代版**：涉钱练习在 frontmatter 加可选 `free_alt: <动作描述>`；微行动卡在有 `free_alt` 时给「不花这钱也可以这样做」的并列选项。
- **家庭功课显式可跳过**：涉及原生家庭的练习（阶段 1 回忆/阶段 3 关系功课）标 `skippable: true`，呈现时明写「这一步可以永远跳过」——是红线不是选项（§8 安全边界）。
- **行为句式**：微行动卡与练习文案用行为句式（「今天做一件…的事」），不用感受句式当任务（「感受一下…」）；用户的感受永远是记录的**附注**而非完成的**证据**——证据是他的行为与原话（§11 三级可观测）。

### 机制验证仪表（M10，读→做→证→叙）

外部机制评审的方法论吸收（**产品内验证**路线已拍板：产品本身就是验证载体，不另跑微信群营）。心态/认知成长类的先天软肋是效果没有外部标准——解法是把「落地」翻译成三级可观测：

- **L1 做了**：行为真的发生（微行动完成记录，行为句式）
- **L2 说了**：用自己的话讲出来（对话摘要/日记/信/微行动感受附注——认知被语言化，"知道"变"他的认知"）
- **L3 续了**：没人催仍在做（评估基线之后隔了时日的自发素材）——认知真正改变的硬证据，进评估 distance 与《变化清单》的判据

**归因前后测**：自评（"你觉得成长了吗"）必然虚高，看归因——让用户描述一次真实困境，看第一反应与归因方式的变化（"我不行/都怪他" → "我当时真正想要的是什么"）。T0 = 体检问卷的场景题（已有）；重述环节 MVP 借阶段评估的素材对比承担，v1.5 周期回顾上正式重述题。

**验证漏斗**（补充进验收指标，每环塌了就是机制那一环错了，不是"用户不行"）：

| 漏斗环节 | 定义 | 用途 |
|---|---|---|
| 首次微行动完成率 | 进入阶段 1 → 完成第一次微行动 | 动作门槛是否够低 |
| 连续 3 天率 | 首次完成后 3 个自然日内再有任意记录 | 早期回路是否成立 |
| **7 天留存（关键断点）** | 首次会话后第 7 个自然日回访 | 陪跑产品的生死线 |
| 完赛/自发继续 | 走完阶段 1 / 阶段 2 后仍有无催促的记录 | L3 续了的直接观测 |
| 归因变化 | 相邻两次评估中场景归因的层级上移（AI 判断，抽检校准） | 心态类唯一可证伪的"落地"证据 |
| **掉队点地图（内部）** | 长间隔回访前最后一次交互是什么（动作太虚？回应缺席？碰到家庭题？） | 抽象产品功能的真正原料——**只进聚合数据，绝不变回对用户的打扰** |

10-20 人量级做不了定量显著性：以深度个案为主（走完全程者的完整记录链 + 掉队者的断点原话），平均值没用。这与「私人个人产品」的体量天然匹配。

## 12. 修订记录

### 2026-09-13 · 程度制标准：灯判定的是「到了什么程度」，不是「做了哪些动作」

用户指正（原话要点）：「这个评估的标准只是用户做了什么、做到了什么程度，而我希望的标准是用户离『一辈子不愁钱的活法』这个目标在本阶段应该达到的程度」。此前的灯标准（灯名+点亮标准）仍是行为句式——「讲出自己的金钱故事」「完成一次不配的小事」「练习做了不止一轮」——数的是动作；评估的真值虽已改为评估结论，但标尺本身还在数动作。修订（用户拍板「按这版全部落地」）：

- **8 盏灯重定义**：每盏灯 = 本阶段离「一辈子不愁钱的活法」应达程度的一个切面。灯名改为程度短语（看得见来历 / 听得见那个声音 / 认得出自己的底色 / 旧脚本被你认领 / 允许过自己 / 话语里有了「可以选」/ 新方式成了日常 / 自己看得见变化）；点亮标准改为程度句式，且写明「做过什么只是证据，状态才是标准」（如 stage2_try：「破例只是证据，『允许了自己』才是标准」）。灯的 kind 不变。
- **评估 prompt 红线**：新增「判定程度，不数动作：灯的标准是『离活法在本阶段应达的程度』，他做过什么只是判断程度的证据——不要核对任务清单、不要数次数」；灯清单引言同步改为「每盏是本阶段应达程度的一个切面——判定的是他到达了这个状态没有」。
- **content advance_when 同步**：阶段 1/2/3 共 8 条推进标志全部改写为程度句式（与 STAGE_LAMPS hint 同构），评估 LLM 拿到的标尺与用户看到的标准一致；阶段 4 文档不动。
- **呈现层零改动**：灯的展示真值维持「最近一次确认评估的结论」（上一条修订），本次只换标尺内容——用户看到的灯名与标准从动作味换为程度味。

### 2026-09-12 · M10：机制验证修订——读→做→证→叙的落地引擎化

来源：消化一轮外部机制评审（核心判断：这本书「读完很感动、第二天照旧」的结构性难题，恰好是本产品的价值所在——**谁能让用户真的做到，谁就赢了这个品类**；用户缺的不是「知道」，是节奏、见证、反馈三样东西，书一样都给不了）。评审原方案是微信群人工营 + 短视频获客（后者按用户指示忽略）；经四项拍板（AskUserQuestion 均选推荐）：**产品内验证**（产品本身就是验证载体，不另跑营）、**维持现有受众定位**、**被看见但不追问**、**轻量承接三仪式**。落地分布：

- **§5 微行动「被看见」闭环**：即时见证回应（收条体，免费）/ 0 元替代版 / 被看见但不追问。
- **§10 内容层规范**：命题标签（六命题）、`free_alt` 0 元替代、家庭功课显式可跳过、行为句式原则。
- **§11 机制验证仪表**：L1 做了 / L2 说了 / L3 续了三级可观测 + 归因前后测 + 验证漏斗六环 + 掉队点地图（内部聚合，绝不变回打扰）。
- **D3 峰值 / D7 复盘 / D14 报告三仪式的翻译**：D3 → 首次微行动的即时回应质量（不做定时任务）；D7 → 归来问候与回访钩子（已有机制承接）；D14 → 阶段评估确认后的**《我变了什么》变化清单**（评估 evidence、信、日记、微行动原话按时间拼装，全免费）——不引入任何倒计时式周期，节奏仍由四阶段承担。
- **评审主张与本产品红线的冲突裁决**：固定追问「今天你做了吗」、断签召回、连续打卡 → **否决**（承 §12 已否决项与 §8 温馨红线）；其合理内核「记录必被回应」保留为硬性设计义务。收小钱入营/对照组 → 随「产品内验证」拍板不采用；对照思想转为漏斗+前后测的内部观测。
- **docs/01 §7 补跨书抽象层**（L1 内容/L2 机制/L3 能力 + 命题索引 + 选书铁律）——为第二本书预埋，不预支实现复杂度。

### 2026-09-12 · M9 二次修订：诊断式评估报告 + 首评前置 + 心印刻度进度条

用户三轮递进（原话要点）：①「固定显示的只有阶段，没有看到进度值，进度需要根据用户的评测、聊天内容等进行评估，需要制定一套评估标准」；②「阶段和进度条，有点像会员积分的等级体系，还差多少分到下级会员等级」（警惕积分/等级味）；③灯列表「不能只是展示用户做了什么……系统需要给用户做详细的评估和反馈……判断用户的底层认知到底当前到什么程度了，什么原因，离一辈子不愁钱的活法还有多远，还要做什么的指导……需要给他直接的诊断，下一步的行动建议」。据此落地（评估标准完整口径已写入 §4「阶段进度评估标准」）：

- **评估报告升级为诊断式四件套**：灯 + 依据之外，每次评估新增**诊断**（为什么是这里——书的机制框架引原话作镜）、**距离**（离活法多远——路标式不恐吓不许诺）、**行动**（2-3 条今天就能开始的小步）；确认后的报告常驻旅程页（「它看见的你」），不再确认即逝。
- **首评前置**：体检完即首评——初谈不结算对话摘要、新用户基线后素材为 0，原素材闸下评估永远不触发；修正为「从未确认过评估的用户，体检画像本身就是证据」，不受新素材条数限制；首评后基线从确认时刻重算。dismiss 首评仍走 14 天冷却。
- **体检画像进评估素材**：问卷原话/说过的话/和钱的瞬间/金钱底色/旧脚本（连同确认状态）作为置顶素材节；choice 类自报选项不进（无语义且诱导违规点灯）。画像是当前态自述，不参与基线过滤，判定时须与这段时间的言行互证。
- **进度条改心印刻度**：原「四段 + 当前段按确认阶段填满」被指有会员等级味，改为各段按**实际点亮的灯**比例填充 + 右侧「已点亮 x/y 盏」；无百分比、无「还差多少」；阶段 4 整段淡色、无计数。
- 温馨红线不变：无打卡/倒计时/红点/惩罚，只增不减，评估不评判不打分不比较。技术上 StageAssessment 扩展、PortraitEvidence 素材、首评闸、诊断式 prompt 与刻度函数见 docs/03 §3/§11。

### 2026-09-12 · M9：旅程整合 + 画像演进 + 阶段进度量化

需求三条：①把所有和用户有关的内容（画像、聊天、心事等）整合到旅程中方便查看；②金钱画像要有演进过程——信息足够时生成新画像，旅程不同时刻画像不同；③用户要能知道自己到了哪个阶段、完成了什么、离下一阶段多远（量化方法与展示，用于激励）。

- **旅程 = 成长过程**（用户澄清）：与既有 /journey 每日节奏页整合——「旅程中的我」区聚合画像/足迹入口与最近三步；`/timeline` 时间线是「改变的见证」而非数据相册。
- **阶段进度量化 = 心印点灯**（用户拍板：游戏化但温馨）：量化的是**已做到的里程碑**，不是未完成任务——无打卡、无倒计时、无红点、断开无惩罚；content weeks 只作「参考节奏约 N 周」静态展示；阶段 4 仍无终点线。初版按交互计数判定，随后按用户语义修正改为认知/行为评估制（见下一条修订记录），计数判定废弃。
- **画像演进**（已拍板：AI 提议 + 用户确认；演进 + 对比全免费）：基线后新摘要 ≥5 条、或距基线 ≥4 周且有任意新素材时提议；「暂不」14 天冷却；生成保留认可过的内容、修正过的不回退、脚本已确认且有证据则保留（`stage3_review` 灯原随画像 version≥2 机械点亮，已随评估制修订改由阶段评估依认知/行为判定）。

### 2026-09-12 · M9 修订：阶段进度改为认知/行为评估制 + 全局进度条

用户对进度语义的修正（原话要点）：「不是指操作了什么回应了什么的进度，而是通过用户的当前表现出的认知、行为来评估他实际所处的阶段的进度（也就是他离核心价值——一辈子不愁钱的活法——已经达成的进度），和在产品中操作、交互的次数没有严格的关系；所有设计是围绕达成核心价值的效果和进展来进行的。」另追加需求：「展示整体进度条，在所有页面上都固定能看到」。据此落地：

- **进度 = 评估出来的位置，不是攒出来的次数**：AI 依据真实素材（对话摘要/日记/微行动与感受/信/画像修正）对照各阶段的样子（content 的 goal/advance_when），评估用户实际表现出的认知与行为走到了哪里；每盏点亮的灯必须给出**依据**（引用原话或具体的事），没看到就如实说没看到，禁止编造。
- **入口 = AI 提议 + 用户确认**（镜像画像演进）：素材攒够（基线后新素材 ≥3 条，或 ≥14 天且有任意新素材）→ 旅程页亮「看看你走到了哪里」→ 用户点头才生成评估 → 结果卡（位置 + 灯 + 依据 + 镜子式总结 + 下一阶段的样子）→「记下现在的样子」确认 /「走进下一阶段」（仅评估认为已到时）/「不是这样的」（14 天冷却，无惩罚）。
- **只增不减**：灯不熄灭、阶段不倒退（评估可以诚实说「这段在原地」，机制不惩罚不回退）；灯的展示真值是**最近一次确认评估的结论**（`assessment.confirmed.lamps`：亮/不亮 + 依据）——灯是评估对认知/行为的判定，不是用户动作的记录，评估没说亮的灯一律不亮；`stamps` 退为确认仪式同步留下的心印存档（足迹/心印陈列用），存量机械时代发的心印不再参与灯判定；旅程渲染不再自动发印——交互数据只是评估原料。
